# BetArena Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a free-to-play, BetPoints-based Betclic clone with real football data, live odds/scores over WebSockets, full bet types (single/acca/system), auto-settlement, friends + leaderboards.

**Architecture:** Single Node process on Fly.io: custom `server.ts` hosting Next.js App Router + Socket.io + in-process scheduler (fixtures/odds/scores/settlement intervals). Postgres via Prisma. Sports data from API-Football + The Odds API behind a rotating free-tier KeyPool.

**Tech Stack:** Next.js 15 (App Router), TypeScript, Tailwind CSS v4, Framer Motion, Zustand, Socket.io, Prisma/Postgres, zod, bcrypt, jose (JWT), canvas-confetti, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-14-betclic-clone-design.md`

## Global Constraints

- No real money anywhere; currency is integer BetPoints; starting balance 1,000.
- Daily bonus +100 (24h cooldown); rescue top-up +500 when balance is 0 (24h cooldown).
- Colors: bg `#121212`, red `#E50813`, white text, win accent `#B9F135`; font Inter.
- Odds change flash: green up / red down. LIVE pill pulses.
- Football only v1; markets: 1X2 (`h2h`), Over/Under 2.5 (`totals`), BTTS (`btts`, hide when unavailable).
- Bet types SINGLE / ACCA / SYSTEM (Trixie 4 combos, Patent 7, Yankee 11, Lucky15 15). Per-combo stake = floor(total/combos), remainder refunded.
- VOID leg: acca odds ×1.00 for that leg; single refunds; system combos re-price.
- Bets are server-authoritative; odds locked at placement; settlement idempotent via leg `settledAt`.
- All scheduler/adapter calls: 10s timeout, error-isolated (never crash process).
- Every task ends green: `tsc --noEmit` + its tests, then commit.
- Dev DB: local Postgres on port 5433 (`DATABASE_URL` in `.env`).

**Accepted deviation (user override "don't stop until built"):** UI tasks specify exact files, props, behavior and design tokens rather than full JSX in this plan; code is written at execution time. All money-path logic (combos, payouts, settlement, keypool) is fully specified below with tests-first.

### Task 3: Betting math — pure functions + tests (TDD)

**Files:** Create `src/lib/betting/combos.ts`, `src/lib/betting/payout.ts`, `tests/combos.test.ts`, `tests/payout.test.ts`.

**Interfaces (Produced):**
```ts
export type SystemType = 'TRIXIE' | 'PATENT' | 'YANKEE' | 'LUCKY15';
export function comboSizes(t: SystemType): number[];            // e.g. TRIXIE -> [2,3]
export function comboCount(t: SystemType): number;              // 4 | 7 | 11 | 15
export function generateCombinations(t: SystemType, legIds: string[]): string[][];
export function splitStake(total: number, count: number): { stake: number; remainder: number };
// payout.ts
export type LegStatus = 'WON' | 'LOST' | 'VOID' | 'OPEN';
export function accaOdds(oddsList: number[]): number;           // product, VOID->1
export function settleCombos(combos: { legIds: string[]; stake: number }[],
                             legStatus: Record<string, LegStatus>,
                             legOdds: Record<string, number>): { payout: number; status: 'WON'|'LOST'|'PARTIAL'|'VOID' };
```
Rules: combination wins iff every leg WON or VOID (VOID contributes odds 1.0); payout = floor(stake × Π odds); combo LOST if any leg LOST; PARTIAL = some combos won, some lost; VOID = all legs void (payout = full stake back).

Steps: write tests for all 4 system types incl. 3/4/5-leg inputs, stake splits with remainders (e.g. total 100 over 7 combos → 14 each, remainder 2), VOID-legend acca (odds [2.0, VOID, 3.0] → 6.0), PARTIAL patent; run red; implement; run green; commit `feat: betting combo and payout math with tests`.

### Task 4: Settlement resolution + tests (TDD)

**Files:** Create `src/lib/betting/settle.ts`, `tests/settle.test.ts`.

**Interface (Produced):**
```ts
export type LegPick = { marketKey: 'h2h'|'totals'|'btts'; selectionKey: string };
// selectionKeys: h2h -> 'home'|'draw'|'away'; totals -> 'over_2.5'|'under_2.5'; btts -> 'btts_yes'|'btts_no'
export function resolveLeg(pick: LegPick, score: { home: number; away: number }): 'WON'|'LOST'|'VOID';
```
Rules: draw impossible result → if selection `draw` and score equal → WON etc.; `over_2.5` ⇔ home+away ≥ 3; `btts_yes` ⇔ both > 0. `VOID` reserved for callers when market missing (function never returns VOID for defined markets — kept in type for caller composition).

Steps: parametrized tests over score grid (0-0, 1-0, 2-1, 3-3, 0-3 …) × all selection keys; red; implement; green; commit `feat: leg resolution rules with tests`.

**Interfaces (Produced):**
```ts
// key-pool.ts
export class KeyPool {
  constructor(keys: string[], opts?: { now?: () => number });
  next(): string;                       // healthy round-robin
  reportFailure(key: string, kind: 'quota' | 'auth' | 'network'): void;
  reportRemaining(key: string, remaining: number, resetEpochMs: number): void;
```

- Pool behavior: exhausted keys cool down until reset epoch; if ALL exhausted, throw `AllKeysExhaustedError` (callers serve cache + stale flag).
- `api-football.ts`: `getFixturesByDate(dateISO)`, `getLiveFixtures()`, `mapFixture(raw)` → normalized `{ providerId, league, kickoff, status, teams, score, minute, events }` (maps their `NS/1H/HT/2H/FT` → `SCHEDULED/LIVE/LIVE/FINISHED`; events from `events[]` goals/cards/subs with zone heuristics).

- Env: `API_FOOTBALL_KEYS`, `ODDS_API_KEYS` CSV. Empty env → adapters inactive, app serves seeded/demo data with `dataStale`.
- Steps: tests for round-robin, quota cooldown w/ fake clock, all-exhausted throw; red; implement; green; commit `feat: key pool and sports api adapters`.

### Task 8: Custom server + Socket.io + scheduler

**Files:** Create `server.ts`, `src/server/socket.ts`, `src/server/scheduler/index.ts`, `src/server/scheduler/fixtures.ts`, `src/server/scheduler/odds.ts`, `src/server/scheduler/scores.ts`, `src/server/scheduler/settlement.ts`; Modify `package.json` scripts (`dev: node server.ts` with NODE_ENV check, `build: next build`).

Socket events (server→client): `odds:update {fixtureId, marketKey, selectionKey, value, previousValue}`, `score:update {fixtureId, homeScore, awayScore, minute, events}`, `bet:settled {betId, status, payout, pointBalance}`, `balance:update`. Client→server: `subscribe:fixture`, `unsubscribe:fixture`, `subscribe:live`. Auth: on handshake read JWT cookie, join `user:{id}`.

Scheduler intervals (all wrapped, sequential-safe, never overlapping via `running` flags): fixtures 6h, scores 60s when any LIVE fixtures else skip, odds 30m pre-match / 90s in-play, settlement 60s. Each upsert diffs to emit socket events (odds changed → emit + `previousValue`).
